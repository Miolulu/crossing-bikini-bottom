## 交付三步

1. **出图**：透明底 PNG、sRGB、8–12% 边距、基线齐平、朝右、≤6 色、描边 `#062338`，命名 `<编号>-<内部代号>[-<状态>][@2x].png`。
2. **改契约**：在 `manifest.json` 里把本批条目 `status` 改为 `delivered`，填 `files`（实际文件名）、`generated_by`、`params_ref`。**只改这 4 个字段**。
3. **存档 + 自检**：填 `art-params.md`（种子 / 模型 / 步数 / 完整提示词 / 负面词 / 抽检记录），跑 `python3 ../tools/validate-assets.py`，输出 PASS 再提交。

## 不要做

- 不要交 JPG / WebP / 白底 / 带文字数字 logo / 带发光投影 / 多主体同图
- 不要交 `code_only: true` 的条目（蟹黄堡、鱼网光标、会话 UI 等由代码绘制）
- 不要改 `src/`、`integration/`、`docs/`、`tools/`
- 不要删废弃稿 —— 移到 `_review/`，文件头加 `⚠️ 本版已废弃（日期）：原因 → 请使用 xxx`
- 不要把 `status` 直接写成 `accepted`（那是集成 AI 验收后才标的）

## 分批即可

不必一次交齐。建议：批次 1 = `B-05` 锁风格 → 六栋建筑 → 全景 → 房间模板；批次 2 = 全 14 房间 + 角色 + 核心道具；批次 3 = 小物 / bot / 图标 / 可选替换。未交的保持 `pending`，集成侧会保留 CSS 占位。

## 状态机

`pending → delivered（你）→ accepted / rejected（集成 AI）`。被退回时看 `assets/_review/退回说明.md`，改完重新标 `delivered`。
