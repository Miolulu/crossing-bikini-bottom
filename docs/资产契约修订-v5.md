# 资产契约修订 v5（2026-11-11）

> 本次修订只涉及「画幅比例的声明方式」，不改资产清单编号、不新增/删除任何交付文件。
> 触发原因：v5 Overhaul 后 `tools/validate-assets.py` 对同一 spec 下的异画幅文件误报 FAIL。

## 1. D 角色：同一条目混装 2:3 立绘与 1:1 token

**现象**：`D-02`~`D-07` 条目 `spec.ratio=0.667`，但条目下的 `-token.png` 是 1:1 圆形徽章，校验报「宽高比偏差 >12%」。

**依据**：`docs/美术资源需求与交付规范.md` §交付规格本身就规定了两套画幅——

| 类别 | 画布 | 宽高比 |
|---|---|---|
| D 角色立绘 | 512 × 768 | 2 : 3 |
| D 世界小 token | 128 × 128 | 1 : 1 |

**修订**：manifest 条目级 `spec.ratio` 只约束主画幅（立绘）；校验脚本新增按文件名种类后缀的覆盖表 `KIND_RATIO`（portrait/walk/sit=0.667，token=1.0），条目仍可用 `spec.ratio_by_kind` 显式覆盖。资产侧落地：

- `-portrait.png` → 512×768，主体高 600、基线 y=700（透明边距 8.7%）
- `-token.png` → 256×256（规范的 128 的 2×，供 92px 头像显示与高分屏），圆形胸像垂直居中

## 2. B 建筑：1:1 画布 → 按主体紧裁的透明画布

**现象**：B-01/02/04/06 报「宽高比偏差 >12%」。

**原因**：旧 1:1 画布配合代码 `object-fit: contain` 会按短边缩放，导致建筑实际渲染只有容器高的 60% 上下——这正是「建筑大小不对」的直接原因之一。v5 已把六栋建筑改为**紧裁画布**（主体占画布约 89%，高统一 526px）。

**修订**：B 类 `spec.ratio` 改为按各资产实际画幅声明（B-01 0.65 / B-02 0.78 / B-03 1.11 / B-04 0.83 / B-05 0.99 / B-06 0.62），`spec.canvas="tight-alpha"`。规范文档「B 类 1:1 画布」条款同步失效，以本文件为准；校验的 12% 容差仍能拦截意外二次裁切。

## 3. 透明边距：token 圆形徽章按圆边距计

圆形 token 的 bbox 贴近圆周，按矩形口径计算会误报「边距偏小」。v5 token 内缩 8.2%（pad 21/256），既满足矩形口径 ≥6% 的告警线，又保持圆徽章的视觉饱满。
