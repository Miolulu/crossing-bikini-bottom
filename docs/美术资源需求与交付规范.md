## 0. 一页速览（先读这 10 条，能避开 90% 的返工）

1. **只写 `assets/`**。仓库里 `src/`、`integration/`、`docs/`、`tools/` 是集成 AI 的地盘，请不要修改，否则合并会冲突。
2. **风格锚点逐字复制**，一个字都不改（§3.1 / §3.2）。跨批次改写锚点 = 素材摆进同一房间立刻露馅。
3. **每条提示词 = 锚点 + 类别模板 + 负面词**，只替换模板里的【】槽位，其余原样。
4. **透明底 PNG / sRGB**，主体四周留 8–12% 透明边距，**基线齐平**，统一**朝右**，单图用色 ≤ 6，描边固定 `#062338`。
5. **交互高亮金 `#FFD23F`、呼吸发光、碎星光、粒子、文字、数字、门牌、号码屏内容一律不进图**——全部由 CSS/HTML 叠加（§4.9 不进图清单）。
6. **双态物件成对生成**，除【状态】槽位外提示词逐字一致；「亮」态只改色块明度，绝不画光晕。
7. **先跑 1 张锁风格**（推荐 B-05），确认描边/饱和度/等角角度后再批量；每 3 张抽检 1 张。
8. **交付三件套**：PNG 文件 + 更新 `assets/manifest.json` 的 `status` + 填写 `assets/art-params.md` 参数存档，缺一不算交付完成。
9. **文件名 = 编号-内部代号-状态.png**，例如 `B-05-krusty_krab-right.png`、`E-02-register-open.png`；纯色底版本加 `-solid`。
10. **交付前跑自检**：`python3 tools/validate-assets.py`，输出 PASS 再把 `status` 改成 `delivered`。

## 1. 项目是什么

一个可连续探索的 2.5D 轻等角海底小镇网页体验（单文件 HTML Demo）：六栋建筑错落散布在**同一个连通世界**里，可进入共 14 个子房间；有 NPC 作息、分支对话、点餐动线、翻找/旋转/开关交互、27 件彩蛋，以及水母田 / 泡泡摊 / 空手道场三处世界内小玩法。

目前 Demo 里的所有视觉都是 **CSS 几何 + 色块 + 文字占位**。你的产出会按编号替换这些占位，因此规范的核心是：**尺寸比例对得上、抠图干净、风格统一、不把动态效果画进静态图**。

### 合规红线

- 提示词里**禁止**出现角色专有名词、作品名、商标、招牌文字；中文资产名（如「蟹堡王」）只用于本清单的人类索引，**不进提示词**。
- 只描述形体、色块、圆润比例与构图气质；招牌只画轮廓、不写字，文字全部由 HTML 渲染。
- 不描摹原作赛璐璐描线与精确造型（负面词里已逐字排除）。

## 2. 美术风格结论

| 候选 | 结论 | 原因 |
|---|---|---|
| **2.5D 轻等角微缩手绘** | ✅ **采用** | 与「连通世界 + 多房间 + 可点物件」最契合；DOM/CSS 分层可直接挂载；单张透明底素材即可复用 |
| 全 3D 建模渲染 | ❌ 否决 | 与现有 DOM 世界引擎不兼容，成本与集成风险高 |
| 原作赛璐璐 2D | ❌ 否决 | 合规风险 + 与轻等角景深冲突 |
| 像素 / 体素 | ❌ 否决 | 与「微缩沙盘手绘质感」目标不符 |

一句话：**儿童绘本般的圆润比例 + 厚而柔和的深蓝描边 + 明快平涂高饱和海底色 + 统一左上方柔光**。

## 5. 设计规范（硬约束）

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | 透明底 PNG、sRGB；主体四周 8–12% 透明边距 | 叠到房间背景上出现白框 / 裁切 |
| 2 | **基线齐平**：同批所有素材的主体底边对齐同一水平线 | 摆进同一房间时高低乱跳 |
| 3 | **统一朝右**；左向由代码镜像 | 需要额外出图、风格易串 |
| 4 | 单图用色 ≤ 6，描边统一 `#062338` | 与既有色板脱节 |
| 5 | **纯色底 / 主体互不重叠**（多主体只用于 A-01 全景） | 抠图无法分离单体 |
| 6 | 负面词逐字排除 `投影 / 落地阴影 / 接触阴影 / 环境光遮蔽` | 透明底抠完留灰黑毛边 |
| 7 | 图内**零文字、零数字、零 logo、零招牌字样** | 与 HTML 文字层重复、合规风险 |
| 8 | 图内**零金色高亮 / 呼吸发光 / 碎星光** | 无法做动画、污染色板 |
| 9 | 双态物件成对、除状态槽位外逐字一致 | 看起来不像同一个物件 |
| 10 | 换色主体单一纯色平涂 + 描边层独立 | 代码无法一键出变体 |
| 11 | 6 套房间主题共用色板，同栋子房间像同一栋楼 | 房间之间割裂 |
| 12 | 位置锚定代替数量词（见 §4.1） | 建筑数量 / 排布失控 |

## 6. 交付规范与交付形式（★ 重点）

### 6.1 交付三件套（缺一不算完成）

| # | 交付物 | 位置 | 说明 |
|---|---|---|---|
| 1 | **PNG 资源文件** | `assets/<子目录>/` | 按 §6.3 命名、按 §6.4 规格 |
| 2 | **`assets/manifest.json` 状态更新** | 仓库根 `assets/` | 把已交付条目的 `status` 从 `pending` 改成 `delivered`，填写 `files`（实际文件名）、`generated_by`、`params_ref` |
| 3 | **`assets/art-params.md` 参数存档** | `assets/` | 平台 / 模型版本 / 种子 / 步数 / 尺寸 / 采样器 / 完整提示词全文 / 负面词版本 / 首批验证图 / 抽检记录 |

> 参数存档是**复现与补图的唯一依据**。没有它，后续补一张同风格素材只能重猜，必然漂移。

### 6.2 目录归属（谁写哪里 —— 协作不冲突的关键）

| 目录 | 归属 | 允许操作 |
|---|---|---|
| `assets/**` | **美术 AI（你）** | 新增 PNG、更新 `manifest.json` 的 `status`/`files`/`generated_by`/`params_ref`、写 `art-params.md`、往 `_review/` 放废弃稿 |
| `assets/_review/` | 美术 AI | 待验收稿、被退回稿；**不删除**，文件头加 `⚠️ 本版已废弃（日期）：原因 → 请使用 xxx` |
| `src/**`、`integration/**`、`tools/**` | **集成 AI** | 你**只读**，不要改 |
| `docs/**` | 集成 AI 维护 | 你只读；若发现规范有错，在 `assets/_review/` 写 `规范异议.md`，由集成 AI 统一改 |
| `previews/**` | 集成 AI | 浏览器实图，供你核对效果 |

**一句话**：你只往 `assets/` 里放文件 + 改 `manifest.json`，其余一律不碰。

### 6.3 文件命名

```
<编号>-<内部代号>-<状态>.png          例：B-05-krusty_krab-right.png
<编号>-<内部代号>-<状态>-solid.png    纯色底版本（可选）
<编号>-<内部代号>-<状态>@2x.png       2× 高清版（可选）
```

- **无状态变体的资产可省略 `<状态>` 段**：如房间背景 `G-01-krusty_hall.png`、portal `G-02-portal_door.png`、图标 `G-05-egg-01.png`。建筑统一用 `-right` 表示朝右（不要省略）。`manifest.json` 的 `files` 字段是文件名的**权威清单**，与其逐字一致即可。
- 编号一套到底：`A` 世界 / `B` 建筑 / `C·G-01` 房间 / `D` 角色 / `E·G-02·G-03·G-04` 道具 / `F` UI / `G-05` 图标 / `G-06~G-13` 扩展，与 `docs/交付产物清单.md` 完全一致。
- **中文资产名只用于清单索引，不进文件名、不进提示词**；文件名一律用 `manifest.json` 里的 `code`（内部代号）。
- 状态后缀：`-right`（朝右）/ `-closed` `-open` / `-off` `-on` / `-front` `-back` / `-portrait` `-token` `-walk` `-sit`。
- **禁止**空格、中文、大写混排、无编号文件、随意的 `final_v2_新.png`。

### 6.4 格式与技术参数

| 项 | 要求 |
|---|---|
| 格式 | PNG（**不要 JPG / WebP / GIF / SVG 位图替代**）、sRGB、含 alpha 通道 |
| 背景 | 透明底（A-01 与房间背景为单一纯色底） |
| 尺寸 | 见 §4.0；1× 必需，2× 可选 |
| 边距 | 主体四周 8–12% 透明像素 |
| 对齐 | 同批基线齐平、主体居中 |
| 色彩 | 单图 ≤6 色，描边 `#062338` |
| 方向 | 统一朝右 |
| 双态 | 成对、同尺寸、同构图，仅状态槽位不同 |
| 元信息 | 不强制；若平台自动写入 EXIF/文本块请保留，不要塞提示词进 PNG 文本块 |

### 6.5 `manifest.json` 状态机（协作握手协议）

`assets/manifest.json` 是**双方唯一的机器可读契约**。字段说明：

| 字段 | 谁改 | 含义 |
|---|---|---|
| `id` | 集成 AI 预置 | 资产编号，唯一，不要改 |
| `slot` | 集成 AI 预置 | 对应 `integration/asset-slots.json` 的代码插槽 key |
| `files` | **美术 AI** | 实际交付的文件名数组，相对 `assets/<dir>/` |
| `status` | **美术 AI**（`pending→delivered`）/ **集成 AI**（`delivered→accepted` 或 `rejected`） | 见下方状态机 |
| `generated_by` | 美术 AI | 平台 / 模型版本，便于追溯 |
| `params_ref` | 美术 AI | 指向 `art-params.md` 里的批次编号 |
| `code_only` | 集成 AI 预置 | `true` = 由代码绘制，**不需要交付** |
| `required` | 集成 AI 预置 | `true` = 必交；`false` = 可选 / 默认 CSS 已实现 |

```
pending  ──美术 AI 放好文件 + 自检 PASS──▶  delivered
                                              │
                        ┌─────────────────────┴─────────────────────┐
                        ▼                                           ▼
                    accepted（集成 AI 已挂载并验收）            rejected（退回，附原因）
                                                                    │
                                                          美术 AI 重做 → delivered
```

- **每次交付只改 `files` / `status` / `generated_by` / `params_ref` 四个字段**，不要重排 JSON、不要改别人的字段，否则合并冲突。
- 分批交付即可，不必一次交齐；`manifest.json` 里未交付的条目保持 `pending`。
- 被退回的条目：集成 AI 把 `status` 设回 `rejected` 并在 `assets/_review/退回说明.md` 写原因；原文件移到 `_review/`，**不要删除**。

### 6.6 三种交付形式（按优先级）

| 形式 | 做法 | 适用 | 推荐度 |
|---|---|---|---|
| **① Git 仓库直交（首选）** | 把 PNG 放进 `assets/<子目录>/`，更新 `manifest.json` 与 `art-params.md`，按 §7.4 约定 commit 并推到共享仓库 | 你与集成 AI 都能访问同一仓库 | ⭐⭐⭐ **首选** |
| **② 打包 zip（备选）** | 保持 `assets/` 完整目录结构 + `manifest.json` + `art-params.md`，打包为 `assets-交付-YYYYMMDD-batchN.zip` 发给人类，由人类或集成 AI 解压合并进仓库 | 你不能 push、或需要先离线验收 | ⭐⭐ |
| **③ 单张散图（兜底，不推荐）** | 按 §6.3 命名逐张发送 | 只补 1–3 张 | ⭐ 容易漏编号 / 漏状态，仅在补图时用 |

> **无论哪种形式，`manifest.json` 都要一起给**。它是集成 AI 判断「哪些图该挂到哪个插槽」的唯一依据，没有它就得靠猜文件名，必然错挂。
> 若走形式 ②，zip 内**顶层必须是 `assets/` 目录**，不要套一层多余的文件夹，也不要带 `_review/` 之外的临时文件。

### 6.7 拒收清单（会被直接 `rejected`）

- JPG / WebP / 非透明底 / 带白底或灰底
- 图里有文字、数字、logo、招牌字样、门牌、号码屏内容
- 图里有金色高亮、呼吸发光、碎星光、粒子、投影 / 落地阴影 / 接触阴影
- 一张图里挤了多个主体（A-01 全景除外）
- 无编号、中文文件名、大小写混乱、缺状态后缀的双态图
- 与 `manifest.json` 对不上、或没更新 `manifest.json`
- 未填 `art-params.md` 参数存档
- 改了 `src/` / `integration/` / `docs/` / `tools/` 里的文件
- 未跑 `tools/validate-assets.py` 就标 `delivered`

### 6.8 验收脚本

```bash
python3 tools/validate-assets.py
```

自动检查：`manifest.json` 结构合法 / 编号唯一 / `status=delivered` 的条目文件是否齐全 / 扩展名与命名正则 / PNG 可解码且含 alpha / 尺寸与宽高比在容差内 / 四角是否透明 / 透明边距是否 ≥8%。输出 `PASS` 或逐条 `FAIL` 原因，并把报告写到 `assets/_review/validation-report.md`。

```
① 集成 AI 建仓：目录骨架 + manifest.json（全部 pending）+ 本文 + 插槽表
        │
② 美术 AI：跑 1 张锁风格（B-05）→ 填 art-params.md → 批量出图 → 自检 PASS
        │  放 assets/<子目录>/，改 manifest.json 对应条目为 delivered，commit + push
        ▼
③ 集成 AI：pull → 跑 validate-assets.py → 按 integration/asset-slots.json 挂载 PNG
        │  替换占位几何 → 浏览器实图验收（无错位 / 无脏边 / 风格统一）
        ├── 通过 → manifest.json 标 accepted，截图存 previews/
        └── 不通过 → 标 rejected + 在 assets/_review/退回说明.md 写原因 → 回到 ②
        ▼
④ 循环按批次推进：L1（全景 + 6 建筑 + 6 主题房间）→ L2（核心道具 + 角色）→ L3（全量）
```

**关键点**：`assets/` 与 `src/` 物理隔离，两边同时提交**不会产生文件级冲突**；唯一可能冲突的是 `manifest.json`，所以约定「**美术 AI 只改 4 个字段、集成 AI 只改 status**」，且双方提交前先 `git pull --rebase`。

### 7.4 commit / 分支约定

- 分支：小批次直接推 `main`；大批量（>20 张）建议 `art/batch-N`，交付后由集成 AI 合并。
- 美术 AI 的 commit message：
  ```
  assets: deliver B-01..B-06 building exteriors (batch 1)
  assets: deliver E-02..E-04 prop pairs (batch 2)
  assets: params lock B-05 seed/model/steps
  ```
- 集成 AI 的 commit message：
  ```
  feat(integration): bind B-* building sprites
  chore(manifest): accept batch 1 / reject E-03-grill (glow painted into PNG)
  ```
- **不要**把 `assets/_review/` 里的废弃稿删掉再 commit；不要 force push；不要重写已 pushed 的历史。

### 7.5 集成回填流程（集成 AI 这边做什么，供你理解交付为何要这么规范）

1. 读取 `assets/manifest.json`，筛出 `status=delivered` 且 `code_only=false` 的条目。
2. 用 `tools/validate-assets.py` 校验文件齐全、命名、alpha、尺寸比例、透明边距。
3. 按 `integration/asset-slots.json` 的 `slot` 把 PNG 挂到 Demo 对应位置：
   - `building.<id>` → `buildings[]` 生成的 `.building` 元素，替换纯色 `background` 为 `background-image`
   - `room.<roomKey>` → `#room` 背景层，替换 `THEME` 渐变
   - `npc.<id>` / `obj.<id>` / `portal.*` → 把 `.ic` 里的文字占位换成 `<img>`，`object-fit: contain`
   - 朝右素材保持原样，左向用 CSS `transform: scaleX(-1)`
4. 浏览器实图验收：与 `previews/` 对照，确认无错位、无脏边、无风格串味、交互热点未被图层遮挡。
5. 通过则 `status=accepted`；不通过则 `rejected` + 写明原因。

> **所以你交的不是「一堆好看的图」，而是「能按编号自动挂进代码的一套资产」**。编号、文件名、目录、manifest 状态，缺一个环节就得人工猜，协作就退化了。

### 7.6 冲突与异议处理

- `manifest.json` 出现冲突：以「同一条目保留双方字段」为原则手工合并，不要整文件覆盖。
- 对规范有异议：在 `assets/_review/规范异议.md` 写清楚（哪条、为什么、建议改成什么），由集成 AI 统一改 `docs/` 并同步方案文档，避免两处规范不一致。
- 风格锚点或负面词**任何改动都必须双向同步** `docs/美术资产规格与提示词包.md` §3/§6 与方案文档 §8.2，否则跨批次必漂移。

## 9. 批量执行顺序（严格按序，别跳步）

| 步 | 动作 | 通过标准 |
|---|---|---|
| 1 | **只生成 1 主体 · 1 状态**（推荐 `B-05` 船形餐厅外观） | 描边粗细、饱和度、等角角度符合锚点；否则调提示词，不要往下走 |
| 2 | 出该主体的**其余状态 / 双态** | 看起来仍是同一个主体，没有串味 |
| 3 | 出**双版本**（透明底 / 纯色底 `-solid`） | 抠图边缘干净、无灰黑脏边 |
| 4 | **锁定参数**：种子 / 模型版本 / 步数 / 尺寸 / 采样器 / 完整提示词全文 / 负面词全文 → 填入 `assets/art-params.md` | 参数已书面存档，可复现；**未填不得批量** |
| 5 | 才按变量槽位表**批量替换**（每次只改【】列） | 每批沿用同一锚点 + 同一负面词 |
| 6 | **每生成 3 张抽检 1 张**，防风格漂移；发现漂移立即回到步骤 4 重锁 | 抽检记录留档 |
| 7 | 按 §6.3 命名归档，放入 `assets/<子目录>/` | 文件名与 `manifest.json` 一一对应 |
| 8 | 更新 `manifest.json` → 跑 `validate-assets.py` → commit + push | 输出 PASS |
| 9 | 集成 AI 挂载实图验收，反馈 `accepted` / `rejected` | 浏览器实图确认无错位、无脏边 |

> 手感/风格未验证就批量，等于把返工成本乘以主体数量。

### 建议批次（对应 §10 的 L1 / L2 / L3）

- **批次 1（L1）**：`B-05` 锁风格 → `B-01..B-06` 六栋建筑 → `A-01` 全景 → `G-01` 六套主题房间模板（先各 1 张验证）。
- **批次 2（L2）**：补齐全 14 张房间 → `D-01..D-09` 角色立绘 + token → `E-02..E-07` 核心道具与双态 → `G-02` portal。
- **批次 3（L3）**：`E-08` 居住区小物、`D-10` bot、`G-05` 图标、`F-16..F-19` 贴纸、可选手绘替换。

## 10. 成本口径（不假定单价）

AI 生图按「调用次数」计费（1 张成图 ≈ 1 次调用），不同平台 / 模型 / 分辨率单价差异极大，**本文件不假定任何具体单价**，只给可复算的调用次数 `C`：`总消耗 = C × P`（P = 账号实际单次单价）。

| 档位 | 覆盖范围 | 成图张数 | 含试错重抽 ×1.35 | ≈ 调用次数 C |
|---|---|---|---|---|
| **L1 降级**（推荐起点） | 世界全景 + 6 建筑外观 + 6 主题房间模板 | ~20 | ×1.35 | **≈ 27** |
| **L2 推荐** | L1 + 核心 40 物件 + 7 立绘 + 13 token | ~95 | ×1.35 | **≈ 130** |
| **L3 完整** | 14 房间 + 60 物件双态 + 全角色 + 27 彩蛋 + UI | ~220 | ×1.35 | **≈ 300** |
| 首批「锁风格」 | 1 主体 × 1 状态 | 1–3 | — | **1–3** |

**降本策略**：① 先跑 1 张锁风格；② 朝右单一方向 + 代码镜像省一半；③ 换色主体单一纯色平涂，代码替换色值出变体；④ 动态效果一律代码叠加；⑤ 蟹黄堡 / 门框 / 光圈 / 进度条等几何件继续 CSS/SVG；⑥ 每 3 张抽检 1 张防漂移。

> 可选手绘替换（G-07 / G-09 / G-10 / G-11 / G-12）最多 **+8～11 次**调用，L1/L2/L3 估算不变；G-08 鱼网与 G-13 会话 UI **永远不生图**。
> **开工前请先向人类确认风格、档位与生图账号**，不要擅自批量生成。

## 11. FAQ

**Q：尺寸必须精确到像素吗？**
A：不必。代码按容器 `contain` 缩放，硬约束是**宽高比、透明底、8–12% 边距、基线齐平**。若你只能出 1024×1024 的建筑图，只要比例 1:1 且边距合规即可，在 `art-params.md` 注明实际尺寸。

**Q：能不能只交一部分？**
A：可以，按批次交。`manifest.json` 里未交的保持 `pending`，集成 AI 会保留 CSS 占位，不会出现破图。

**Q：为什么这么多东西「不要交」？**
A：它们已经由 CSS/SVG 实现且需要动画（呼吸发光、数字翻滚、泡泡飘动、水母触须摆动）。静态 PNG 做不了动画，画进去反而会和代码层重复、污染色板与抠图。

**Q：我改不了 `docs/`，发现规范有错怎么办？**
A：写 `assets/_review/规范异议.md`，集成 AI 会统一改并同步到方案文档，保证全仓只有一份权威口径。

**Q：另一个 AI（集成 AI）怎么知道哪张图挂哪里？**
A：靠 `manifest.json` 的 `id` + `slot`，以及 `integration/asset-slots.json` 的映射表。所以**文件名和编号不能错**。

**Q：我不能直接 push 到 Git 仓库怎么办？**
A：走 §6.6 形式 ②：打包 `assets-交付-YYYYMMDD-batchN.zip`（顶层必须是 `assets/`，含 `manifest.json` 与 `art-params.md`），交给人类放进仓库即可，集成流程完全一样。
