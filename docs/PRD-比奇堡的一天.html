比奇堡的一天A DAY IN BIKINI BOTTOM

你从海面下沉，海水一寸寸爬满屏幕。等光透进来的时候，你已经不是游客了——
你是比奇堡的居民，有自己的名字、自己的身份，和一条必须排队的蟹黄堡队伍。

多人在线 · 第三人称6 座可进入建筑身份随机分配系统3D 蟹黄堡v1.1 · 需求与体验设计

00一页纸摘要

如果你只读一页，请读这一页。这里定义了这个产品是什么、玩家在 5 分钟里会经历什么、以及 Demo 必须证明哪几件事。

一句话定义：一个以《海绵宝宝》比奇堡为舞台的多人在线海底漫步网站。用户打开即被随机分配为一名比奇堡居民，以第三人称在其中生活 10–20 分钟：进别人的家、被章鱼哥嫌弃、跟海绵宝宝一起唱歌、在蟹堡王排队买一个能 3D 旋转、能一口口吃掉的蟹黄堡，并和同屏的其他居民打个招呼。

它不是什么：不是游戏（没有战斗、没有任务链、没有成长数值）、不是聊天室（不开放自由打字）、不是开放世界（Demo 只有一条贝壳街 + 六栋建筑内景）。它的对手不是游戏，而是"点开就关掉的品牌互动 H5"。

Demo 要证明的三件事：

  1. 开场 5 秒能让人"沉下去"——海水铺满屏幕那一刻的沉浸感，是这个产品的第一道门槛。
  2. NPC 真的有性格——章鱼哥的冷漠必须让人"有点被冒犯但又想笑"，而不是一个复读机。
  3. 蟹黄堡值得排队——排队的过程不无聊，拿到手之后"转着看、咬着吃"的手感成立。
5 秒开场沉浸窗口
10–20 分钟单次体验时长目标
6 座可进入建筑
12%彩蛋身份总概率
本文档的使用方式 全文的体验描述都可以改，但有三类内容改动成本最高，建议先确认：① 身份分配的概率与稀有度（影响玩家晒图动机与服务器设计）；② 蟹堡王排队参数（决定"等待是否有趣"）；③ NPC 台词量级（每个 NPC 至少 30 条台词才能撑住 15 分钟不重复）。

01体验愿景与设计支柱

好的主题衍生作品，不是"把角色贴到页面上"，而是"让用户短暂地成为这个世界的一部分"。这个项目的核心情绪是：被一个有点荒诞、有点吵闹、但莫名温暖的小镇接纳。

1.1 核心情绪曲线

一次完整访问应该像一集 11 分钟的动画短片，情绪有起伏而不是平铺：

阶段玩家在做什么目标情绪设计手段
0–1 分钟
下潜		看开场动画、等待加载好奇 + 轻微失重感海水从底部涨满屏幕、光柱、气泡音；文案只有一句"正在前往比奇堡"
1–3 分钟
被认领		抽取身份、看到自己的样子惊喜 / 一点点"我居然是它"的荒谬感泡泡破裂式开卡；身份卡带稀有度与一句专属台词
3–8 分钟
闲逛		走进三栋房子、乱点物品探索欲 + 被 NPC"怼"的乐趣每个物品都有反馈；章鱼哥的冷漠形成反差喜感
8–15 分钟
排队		在蟹堡王取号、等叫号、搭话轻微焦躁 → 拿到食物的满足等待期间有可看的内容（煎肉饼表演、章鱼哥吐槽）
15–20 分钟
吃		堂食或边走边吃，和陌生人招手治愈、想截图分享蟹黄堡 3D 旋转 + 六口吃完的动效；同屏玩家招手回礼

1.2 五条设计支柱

① 身份即角色，不是"游客皮肤"

用户不是"来参观比奇堡的人"，而是"本来就在这儿住的人"。所以：没有"欢迎光临"的官方口吻，NPC 认识你、也未必喜欢你；分配到的身份会改变 NPC 的态度、可触发的彩蛋、甚至移动速度。

② 人设不容妥协

章鱼哥必须真的冷漠、蟹老板必须真的贪财、痞老板必须真的想偷配方。宁可让用户"有点被冒犯"，也不要把所有 NPC 磨平成同一种热情客服。

③ 每扇门都能推，每个东西都能碰

六栋建筑全部可进入；每栋内部至少 8 个可交互物品，且每个物品都有独立反馈（台词 / 动画 / 音效 / 小彩蛋），不做"装饰性家具"。

④ 低压力社交

能看到别人、能打招呼，但不能自由打字。社交设计的目标是"在场感"，不是"社交压力"。陌生人之间的互动上限是一次招手和一个气泡。

⑤ 把一件事做穿：蟹黄堡

整个 Demo 只有一样"可以吃的东西"，所以它必须做到极致：能转、能看、能咬、能掉渣、能吃出满足感。这是全站唯一的重资产动画。

⑥（约束）不做的事

这个项目不是一款游戏，是一个"可走进去的动画片 / 互动体验"。所以不做战斗、不做任务、不做养成、不做自由聊天、不做无缝大世界，尤其不做任何以"留存 / 奖励 / 进度"为目标的系统：每日签到、连续登录、成就、排行榜、体力 / 货币都一律不做（见 Q4）。任何"再加一个系统"的提议，先问它是否强化上面五条；凡是把用户往"每天回来打卡"方向推的，直接否。

1.3 目标用户与场景

用户类型进入场景他们想要什么 / 我们要给什么
童年情怀党（20–35 岁）社交平台看到截图 / 朋友转发想要"回到小时候"的一击。给：开场动画、原作级建筑还原、章鱼哥的经典冷漠。
角色厨想抽到某个角色想要"我是珊迪 / 我是痞老板"。给：稀有身份、专属彩蛋、可截图的身份卡。
闲逛型用户碎片时间、通勤想要不费脑子的 5 分钟。给：不需要教程，进门就能走，任意点击都有反馈。

明确排除：硬核玩家、需要长期目标留存的用户。这类用户会在 20 分钟内离开，这是设计意图，不是失败。

02视觉与听觉基调

整体原则：2D 手绘卡通的"纸质"质感 + 3D 空间的"可走进去"的纵深。用 3D 建场景、用卡通着色（Cel Shading）把 3D 压回 2D 的观感，让画面看起来像一集动画，但你能在里面走动。

04身份分配系统

这是整个产品最有传播力的一环："你会是谁"。设计上有两个必须同时满足的矛盾目标——大多数人应该抽到"普通居民"（保证世界真实、人人都是路人），但少数人必须抽到彩蛋角色（保证有惊喜、有晒图）。

4.1 分配流程

进入贝壳街→0.8s 后，一枚泡泡从上方飘下→点击泡泡（或 3s 自动）→泡泡破裂，展开身份卡
身份卡：头像 + 名字 + 稀有度 + 一句专属台词→"这是我"（确认）→角色模型就位，HUD 出现身份徽章

关键细节：不要在开场前告诉用户"你会被分配角色"。让它在落地后突然发生，惊喜感来自"我已经在这儿了，然后有人告诉我我是谁"。

06主 NPC 人物设定

这一节是整份文档里最重要的部分。四个主角 NPC 的"不好相处"必须被精确地写出来——他们的性格不是配色和台词，而是"什么情况下他们会拒绝你"。

NPC 设计的通用规则（四个角色都适用）
  1. 每人至少 30 条台词，按"心情"分 3 组（友好 / 中立 / 不耐烦），每组 ≥ 10 条。
  2. 拒绝也是一种交互：不给予任务、不提供奖励、不允许进入，都可以是"内容"，只要拒绝的方式符合角色。
  3. 连续交互要有衰减：同一 NPC 在 30 秒内被重复搭话 3 次以上，切到"不耐烦组"，且不重复同一句。
  4. 不许说客服话术：禁用"欢迎光临""有什么可以帮您""感谢您的体验"。NPC 不认识"用户体验"这个词。

6.1 章鱼哥 · Squidward Tentacles

章鱼哥 SQUIDWARD · 收银员 / 自封艺术家

性格内核：他相信自己是被困在收银台后面的艺术家。冷漠不是因为讨厌你，而是因为他觉得"和你说话"这件事本身在消耗他宝贵的创作时间。他的刻薄是有礼貌的刻薄——用词讲究，语气不耐烦。

说话规则：① 句子短，多用停顿和省略号；② 讽刺使用"夸张的礼貌"（"哦，当然。当然。请便。"）；③ 从不主动提问，除非是"你还不走？"；④ 被夸会短暂得意，然后立刻否认。

第一次搭话……有事？没事的话，我在练习。
被连续打扰 3 次你还在这儿。真好。比奇堡最不缺的就是"还在这儿"的人。
你夸他的画（停顿）……你懂艺术？
（0.5 秒后）算了，你只是客气。别碰画框。

口头禅：“我没空。”“随便你。”“……真好。”
专属动作：抱臂、翻白眼、叹气时肩膀下沉 3cm、擦杯子（擦到杯子反光）

分享本地保存为主；如需外部分享，引导用户自己发（不在站内做转发链，避免诱导分享的游戏化感）
彩蛋痞老板身份合影时，画面角落会自动多一只偷偷举着相机的凯伦；小蜗合影只显示一团"喵"字云

11UI / UX 规范

原则：UI 要像海底世界的一部分——圆角、气泡、贝壳、木质纹理，不做科技感面板。任何面板出现都不应该遮住画面中心 40%。

11.1 HUD 布局

区域内容规范
左下身份卡（头像 + 名字 + 身份徽章）72×72 圆形头像，点击展开详情（含专属台词与彩蛋进度）
右下动作轮盘（招手 / 表情 / 短句）默认收起为一个小气泡按钮，点击展开扇形；触屏用长按
右上小地图 + 在线人数极简线稿地图，只标 6 栋建筑图标与自己的点；人数显示"这条街上 12 人"
顶部中央气泡提示（任务性文案）只在必要时出现，如"你拿到了 07 号"
底部中央对话框宽 720px，圆角 18px，米色纸底 + 深海蓝文字

11.2 交互提示三级

  1. 远距离（> 8m）：物体不发生任何变化。不要提前高亮，会变成"满地都是可点击"的游戏感。
  2. 中距离（2–8m）：物体边缘出现极淡的呼吸描边（青色，透明度 0.2）。
  3. 近距离（< 2m）：描边变实，物体上方浮出按键提示（PC 显示 E，移动端显示手形图标）。

11.3 对话系统（双层）

层内容规则
头顶气泡1–2 行，≤ 28 字短、快、有性格；3 秒后自动消失；多人同时说话时最多同屏 3 个气泡
底部对话框完整台词（≤ 90 字）点击 / 空格继续；对话中禁止移动（避免走出镜头）
选项0–3 个只在关键节点给选项（如"要不要帮我偷配方？"→ 答应 / 拒绝 / 装没听见）

11.4 无障碍与移动端

  • 移动端：左半屏虚拟摇杆，右半屏拖拽转视角；交互提示自动切换为手形图标。
  • 键盘：WASD / 方向键移动，E 交互，Esc 关闭面板，Tab 展开身份卡。
  • 对比度：所有文字与底色对比度 ≥ 4.5:1；不用纯色块压图。
  • 「减少动态效果」：关闭镜头下潜、粒子、屏幕震动，保留淡入淡出。
  • 字幕：所有音效关键信息（叫号、门铃）必须有文字提示，不依赖听觉。

12技术实现方案（建议，非强制）

核心判断：用 Three.js 做 3D 场景 + 卡通着色，但把"卡通感"交给后处理与描边，而不是靠高模高贴图。这样在 15MB 的包体预算内可以做出"能走进去的动画片"。

12.1 技术栈

层选型理由
渲染Three.js r160+ / WebGL2生态成熟、卡通着色与后处理现成；不选 Unity WebGL（包体 30MB 起，首屏太慢）
卡通效果MeshToonMaterial + 背面外扩描边（0.02）+ 3 阶 ramp成本低，风格稳定；描边用 BackSide 复制体，比后处理边缘检测更"手绘"
水体顶点波动 + 焦散贴图 + 体积雾（线性雾 30–120m）海底氛围的 80% 来自雾和光柱，不是水模型
后处理Bloom（阈值 0.85，强度 0.6）+ 轻微暗角只加这两个，别加景深（手机端太贵）
动画Mixamo 基础骨骼 + 手工关键帧；NPC 用状态机NPC 动作少而准（章鱼哥 4 个动作就够）
后端Node 20 + Colyseus（或 uWebSockets.js）房间模型天然匹配"街区 = 房间"；tick 15Hz
